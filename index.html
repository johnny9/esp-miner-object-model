ESP-Miner Object Model

Complete runtime architecture of upstream ESP-Miner—covering the static GlobalState root, pinned FreeRTOS task hierarchy, Stratum V1/V2 Noise supervision, BM13xx ASIC pipeline, board-driven power/thermal control, and external AxeOS/Display/BAP surfaces down to the ESP-IDF & hardware boundary.

Shared GlobalState RootOne static GlobalState in main.c passed by pointer to every task, HTTP handler, LVGL screen, and BAP service.
Priority-Tiered FreeRTOS TasksMining hot path runs at prio 20/16/15 (create_jobs, stratum, ASIC_result); power/fan at 10/8; telemetry/UI at 1–7.
Table-Driven Board DispatchDeviceConfig → FamilyConfig → AsicConfig selects BM1366/68/70/73/97, TPS546/DS4432U/INA260, and EMC2101/2103/2302/TMP1075.
Fixed Slots & PSRAM OffloadPre-allocated miner_job_pool_t (8 slots/pool) + mutex-guarded asic_job_store_t; large stacks, coinbase buffers, cJSON & logs live in PSRAM.

Three Core Architectural Patterns

1. Mining Hot Path (Task Notify + Fixed Slots)

stratum_task writes parsed templates into PoolSession.job_pool (8 slots) and wakes create_jobs_task via xTaskNotify carrying (pool_idx, slot). ASIC_send_job claims an asic_job_store_t slot; ASIC_result_task decodes UART1 frames, verifies SHA-256 PoW, and calls stratum_submit_share directly.

2. Board-Capability Dispatch

device_config_init() resolves board version from NVS/efuse into DeviceConfig (pins, family, ASIC, IC presence bitfields). Shared facades (ASIC_*, VCORE_*, Power_*, Thermal_*) switch on those flags so tasks stay board-agnostic.

3. Shared-Memory Snapshot Telemetry

POWER_MANAGEMENT_task, FAN_CONTROLLER_task, hashrate_monitor_task, and statistics_task update fields in GlobalState; http_server, websocket_api_task, screen.c, and BAP read snapshots without duplicating models.

03 Execution, Notification & Slot Contracts

The mining hot path avoids heap allocation and dynamic task creation by combining a protocol vtable, FreeRTOS direct-to-task notifications, and fixed-size job rings.

Core C Contracts (stratum_driver.h, pool.h, asic_job_slot.h)

// Protocol-polymorphic Stratum driver vtable (V1 JSON-RPC & V2 Noise)
typedef struct stratum_driver {
    stratum_protocol_t protocol;
    const char *name;
    esp_err_t (*run)(GlobalState *gs, uint16_t pool_idx);
    void (*close_connection)(GlobalState *gs, uint16_t pool_idx);
    void (*abort_connection)(uint16_t pool_idx);
    int  (*submit_share)(GlobalState *gs, const asic_job_t *job,
                         uint32_t nonce, uint32_t rolled_version,
                         uint64_t *sent_time_us);
} stratum_driver_t;

// Direct-to-task notification payload: stratum_task -> create_jobs_task
#define POOL_JOB_NOTIFY_FLAG (1UL << 30)
static inline uint32_t POOL_encode_job_notification(uint16_t pool_idx, uint8_t slot) {
    return POOL_JOB_NOTIFY_FLAG | (((uint32_t)(pool_idx & 0xFF)) << 8)
                                | ((uint32_t)(slot % MINER_JOB_POOL_SIZE));
}

// Mutex-guarded ASIC hardware job slot ring (copy-out snapshot semantics)
typedef struct asic_job_store {
    asic_job_slot_entry_t *entries;
    uint16_t capacity;
    uint16_t current_slot;
    pthread_mutex_t lock;
} asic_job_store_t;
uint16_t asic_job_store_claim(asic_job_store_t *store, const asic_job_t *job);
bool     asic_job_store_lookup(asic_job_store_t *store, uint16_t slot, asic_job_t *out_job);

Key Runtime Invariants (Verified at 4db592d)

  • Submit timing recorded before socket write (#2085): Both V1 and V2 clients call POOL_timing_record(gs, pool_idx, uid, now) before writing to the transport and clear the slot on write failure, preventing a fast pool reply on RX from racing ahead of TX timestamping.
  • Active-pool share gating: stratum_submit_share() checks active_job->pool_id == active_pool_idx and each protocol driver checks its bounded active_job_ids ring under s_v{1,2}_conn_mutex before writing to the socket.
  • Copy-out ASIC job snapshots: ASIC_process_work() resolves the chip's job ID through asic_job_store_lookup() into task_result.job so later slot reuse by create_jobs_task cannot mutate the job under verification.
  • Clean-job preemption vs. non-clean throttling: create_jobs_task wakes immediately on clean_jobs=true or CREATE_JOBS_NOTIFY_CLEAR_WORK, while non-clean updates respect MIN_JOB_RUNTIME_MS (1000 ms) so rapid pool refreshes don't thrash ASIC pipelines.
  • Two-worker primary/fallback Stratum supervision: Primary task stays resident forever; fallback task (stratum_fb) is dynamically spawned after 3 primary failures (or forced fallback) and calls vTaskDelete(NULL) once primary delivers fresh work and hands over.
  • Graceful degraded boot: If SYSTEM_init_peripherals() fails, app_main skips power/fan/ASIC tasks but still starts AxeOS HTTP server & Wi-Fi so the user can inspect faults or reflash.

1. Boot Sequence, Board Resolution & Degraded Mode

Key boot guarantees:
  • asic_hold_reset_low() runs before NVS and I2C init to keep ASIC power draw minimal during early boot.
  • SNTP callback on_ntp_sync() calls sv2_noise_set_clock_trusted(true) so Stratum V2 Noise certificates validate against a trusted clock.
  • When SELF_TEST_MODULE.is_active is true, Wi-Fi/HTTP/Stratum are bypassed and self_test_task runs hardware qualification directly.

Key pool supervision rules:
  • Primary retries 3 times (2 s delay), then activates fallback (stratum_fb) and probes primary every 30 s (RECOVERY_PROBE_INTERVAL_MS).

  • BAP uses a PSRAM send queue (bap_uart_send_queue) and separate bap_uart_send_mutex / bap_subscription_mutex locks; disabled automatically when DEVICE_CONFIG.pins.bap == NULL.
